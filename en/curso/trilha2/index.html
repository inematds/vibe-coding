🧠 Agentic Workflows & the WAT Framework

The mindset and architecture behind all agentic automation: the on-demand assistant, deterministic vs. non-deterministic, the three WAT layers, the self-improvement loop, the professional CLAUDE.md, and the first agentic workflow.

Module progress 0% · 0 of 9
What it is:

Use the coding assistant as an on-demand personal helper: it researches, builds files, and gets smarter with each use — all running locally.

Why learn:

Seeing the agent work locally first builds intuition before adding complexity (deployment comes later).

Key concepts:

Research and build assistant; no hosting at this stage; two example projects (research and slides).

What it is:

Instead of connecting and configuring each step, you tell the agent the outcome you want; it reasons, adapts, and figures out the steps.

Why learn:

It's the central mindset shift — asking for the finished dish instead of following the recipe.

Key concepts:

Describe the end result; the agent reasons, adapts, and self-heals; think of an experienced developer.

What it is:

Traditional automation is predictable (“boring is beautiful”); generative AI is non-deterministic by nature — the same input can produce different outputs.

Why learn:

Accepting variation keeps you from interpreting it as an error; you focus on specifying outcomes.

Key concepts:

Predictability vs. creativity; the agent reasons through alternatives; variation is normal.

What it is:

Workflows are Markdown files written in natural language (headings, bullets, bold text) that act like a job description or SOP, telling the agent what to do.

Why learn:

It's the framework's first layer — reusable instructions that persist across tasks.

Key concepts:

Markdown as an SOP; objective, input, output, and steps; persistent and reusable.

What it is:

The agent is the code assistant itself: the brain/coordinator that reads the workflows, sees the available tools, and decides which one to use and when.

Why learn:

Understanding that the agent delegates like a project manager clarifies who does what in WAT.

Key concepts:

Coordinator/brain; reads workflows + sees tools; decides the route.

What it is:

The tools are Python scripts that do the actual work, ideally one task each (scrape a website, generate a PDF, analyze data); the AI writes and fixes them.

Why learn:

You don’t need to program—just know the tools exist and what each one does.

Key concepts:

One job per tool; generated and repaired by AI; no coding knowledge required.

What it is:

The agent runs a workflow, finds an error, diagnoses it, fixes the tool, and updates the workflow file so the error doesn’t happen again.

Why learn:

It's what makes runs smoother and faster over time — the system improves on its own.

Key concepts:

Diagnose → fix → document; the fix persists in the workflow; continuous improvement.

What it is:

An onboarding CLAUDE.md that specifies the WAT framework, operating rules, folder structure (workflows/tools/temporary/.env), and style.

Why learn:

It's the document that drives fully automated workflows; keeping it concise prevents rules from getting lost.

Key concepts:

WAT onboarding; default folders; keep it under ~500 lines; move details to skills.

What it is:

Put WAT into action: turn a file of raw notes into a clean, structured document by going through the iteration loop.

Why learn:

It's the first complete build — generates workflows + tools, runs, reviews, and iterates.

Key concepts:

Plan Mode; separate building from execution; feedback that updates the workflow + tool; clear the context.

🔗 Extending the Agent: MCP & Research

Give the agent superpowers by connecting external tools: what MCP is, where to find servers, how to install and troubleshoot them, and an end-to-end research workflow with Firecrawl, from the output pipeline to iteration and self-healing.

Module progress 0% · 0 of 7
What it is:

MCP is a protocol that lets a single connection expose many tools/actions; the agent figures out which one to call, when, and with which parameters.

Why learn:

It's the standard way to give the agent new capabilities without rewriting anything.

Key concepts:

A single connection exposes actions; the agent decides on its own; Gmail analogy (send/draft/read).

What it is:

MCP servers live in directories (like mcp.so) and in GitHub search for "MCP server" + service name.

Why learn:

Knowing where to look speeds up choosing the right tool for the task.

Key concepts:

Categories: scraping (Firecrawl), databases (Postgres/Supabase), documents (Drive/Notion), communication (Slack/Gmail).

What it is:

Give the agent the provider’s documentation installation command; it generates the .mcp.json with the server entry and a key placeholder.

Why learn:

Setup is simple, but the key must be entered carefully to avoid exposing it.

Key concepts:

Provider command; generated .mcp.json; enter the key manually, never in chat.

What it is:

The command /mcp shows the installed servers and their status; if one doesn't appear, restarting the assistant usually resolves it.

Why learn:

Knowing how to verify saves hours spent thinking the installation failed.

Key concepts:

/mcp lists the status; restarting registers new servers; a common cause of “not showing up.”

What it is:

An end-to-end workflow: provide a topic, research the web with Firecrawl, synthesize findings, and generate a structured document (plan → build → run).

Why learn:

It's the build that demonstrates MCP in real use by reusing the WAT framework.

Key concepts:

Plan Mode; target sources (3-5); CLAUDE.md WAT as config; Firecrawl scrapes multiple sources.

What it is:

Produce Markdown and convert it into a document file using a generated conversion tool.

Why learn:

Separating content (markdown) from format (document) makes the output flexible and reusable.

Key concepts:

Markdown first; conversion tool; updating Markdown doesn’t always update the document.

What it is:

Give specific feedback ("I like this; change that") and, if something breaks, ask the AI to fix itself (self-healing loop).

Why learn:

The first run is rarely perfect; the loop is what leads to quality.

Key concepts:

Structured feedback; the more specific, the better; ask it to fix itself.

🧰 Skills, Artifact Generation & Tokens

Package workflows as reusable commands and master the context budget: what skills are, skill vs. typing it out, skills in practice, slide generator, 5 prompting patterns, context rot, /clear vs /compact, token savings, and 12 final tips.

Module progress 0% · 0 of 9
What it is:

Skills are instructions in markdown in a special skills folder, conceptually identical to workflows but invocable as a slash command.

Why learn:

It's how you make a workflow reusable, consistent, and token-efficient.

Key concepts:

The .claude/skills folder; one folder per skill; slash command; loaded on demand.

What it is:

Package a skill when there’s repetition, a need for consistency, complexity, or team sharing; type it out for a one-off or simple task.

Why learn:

Avoid creating too many skills (overkill) or needlessly repeating complex instructions.

Key concepts:

Repetition/consistency/complexity/team → skill; one-off/experiment/simple → type it.

What it is:

Build an "draft email" skill in the official format, with SKILL.md (name, description, arguments, steps), and invoke it as /draft-email.

Why learn:

Shows how a skill becomes instantly reusable with the same rules on every call.

Key concepts:

SKILL.md; arguments (bullets, recipient, tone); invoking without arguments prompts for what's missing.

What it is:

Another WAT build: a workflow that reads a document, extracts the key points, and generates a professional presentation.

Why learn:

Reinforces the CLAUDE.md (WAT) flow → workflow + tools → run → iterate in another artifact.

Key concepts:

Extract key points; style; iterate on colors/fonts; layer on a design skill.

What it is:

Five patterns for consistent results: objective (not steps), specific output, Plan Mode first, feedback (not correction), and treating AI as an expert.

Why learn:

These are habits that improve the quality of any agentic build.

Key concepts:

You’re the manager, the AI is the developer; give feedback instead of saying “that’s wrong.”

What it is:

Context rot: quality degrades as the session gets longer; errors become more common after ~60% usage, when noisy history drowns out the core rules.

Why learn:

Recognizing the zones prevents silent quality loss.

Key concepts:

Zones 0-50 (OK), 50-70 (yellow), 70-85 (orange), 85%+ (clear).

What it is:

/clear resets the entire conversation; /compact creates an intelligent summary that preserves the essentials and compresses the rest.

Why learn:

Choosing the right tool preserves useful context without carrying clutter.

Key concepts:

Clear when switching tasks / when quality degrades; compact midway as the context grows.

What it is:

Strategies to spend less: one task per session, then clear it; define "done"; use skills instead of a giant CLAUDE.md; turn off unused MCPs.

Why learn:

Without a defined endpoint, the agent may search too much and waste tokens.

Key concepts:

Definition of "done"; skills save context; each active MCP uses context.

What it is:

A checklist of 12 best practices for building high-quality agentic workflows, from Plan Mode to context management.

Why learn:

Consolidates everything from the track into a quick reference guide.

Key concepts:

Always use Plan Mode; set a clear goal; define "done"; test with multiple inputs; review early.
