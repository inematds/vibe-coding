1.1 ~45 min

🧩 Fundamentals & Environment

From the concept to a connected, verified environment: what vibe coding is, the coding assistant in the editor, the CLAUDE.md, n8n via MCP, the skills, and the 4-connection check.

Module progress 0% · 0 of 6
What it is:

Build software and automations by talking to AI in natural language — you describe the result, and it handles the implementation.

Why learn:

Removes technical overhead: focuses on the problem, not the mechanics of each node. Speed and fast iteration.

Key concepts:

Natural language drives the build; AI does the "heavy lifting"; iterating just means asking for a change.

What it is:

An assistant that runs inside the editor: reads files, writes/edits, runs commands, and connects tools via MCP.

Why learn:

Understanding subscription (fixed fee, chat-based) vs. API (usage/token-based) helps avoid cost surprises.

Key concepts:

The AI rereads the entire conversation with every message; focused sessions cost less; "one folder per project".

What it is:

One folder per project + a CLAUDE.md markdown file that works as a persistent system prompt (role, context, preferences).

Why learn:

Defines who the AI is and how it should help throughout the project, without repeating context in every conversation.

Key concepts:

Generate via a natural language request; editable at any time; start with an empty folder.

What it is:

n8n is a visual workflow builder; an MCP server connects it to the AI, which can then read, create, test, and debug workflows.

Why learn:

It's the bridge that lets you build automations by chatting, without manually assembling them node by node.

Key concepts:

Clone manually (not NPX); project-level config; API key + instance URL only in .env.

What it is:

Documentation that teaches AI about n8n node types, parameters, structures, and patterns.

Why learn:

With skills, AI builds the right workflows — you don't need to know every node.

Key concepts:

Installation is the same as for the MCP (only the repo changes); update CLAUDE.md; restart to register it.

What it is:

A sequence of 4 tests before building: project directory, MCP connection, workflow reading, and node documentation.

Why learn:

Ensures the environment is 100% ready — avoids wasting time debugging setup in the middle of a build.

Key concepts:

Four tests; common errors (partial API key, MCP won't connect, auth fails); let the AI diagnose.

1.2 ~60 min

🔁 The Complete Cycle: Plan → Build → Troubleshoot → Optimize

The four-phase cycle, demonstrated in an email support agent with RAG: permission modes, plan, build, OAuth credentials, troubleshoot, optimize, project guide, and tests.

Module progress 0% · 0 of 8
What it is:

The modes that control how much the AI can do on its own: ask first, edit automatically, plan, auto, bypass.

Why learn:

Balance speed and security — know when to let the AI act and when to approve each step.

Key concepts:

Plan Mode plans without taking action; bypass skips approvals (dangerous); choose the mode based on context.

What it is:

The AI researches nodes, asks clarifying questions, and proposes a plan for you to approve before building.

Why learn:

Align expectations before spending tokens building the wrong thing.

Key concepts:

Questions (columns, extra actions); an approvable plan; pattern research.

What it is:

The AI creates and validates the nodes in n8n based on the approved plan.

Why learn:

Know the limits: credentials, spreadsheets, and mapping are up to you.

Key concepts:

Automatic creation + validation; clear boundaries between AI and human.

What it is:

Securely connect Gmail/Google Sheets (OAuth2) and OpenAI (API key).

Why learn:

It's the part only you can do; understanding the flow prevents permission errors.

Key concepts:

OAuth2 for Google; API key for OpenAI; never put secrets in chat.

What it is:

Copy the error message back to the AI to diagnose and fix.

Why learn:

The human debugging loop is the core skill—errors quickly become fixes.

Key concepts:

Errors as input; iteration; the AI reads, understands, and proposes a fix.

What it is:

Ask for improvements through conversation—for example, changing the polling interval.

Why learn:

Refine without reopening the build; the workflow evolves through conversation.

Key concepts:

Incremental changes; natural language; small, safe adjustments.

What it is:

An agent that classifies emails, searches policy PDFs (vector store), and drafts replies.

Why learn:

It's the project that ties the whole cycle together in a real, useful use case.

Key concepts:

RAG; text classifier; answers based on the knowledge base.

What it is:

Visual checklist + test real scenarios; “green” in the editor doesn't mean the response is correct.

Why learn:

Prevent the agent from making up what it doesn't know—real quality, not just execution without errors.

Key concepts:

Test as a user; the AI should refuse to make things up; green ≠ correct.

✨ From “It Works” to “It Works Well”: Enhancement

Turn a workflow that “passes the tests” into one that's ready for the real world: layered philosophy, priority order, fallback, filters, brand voice, personalization, and a confidence indicator.

Module progress 0% · 0 of 8
What it is:

Iterate on one improvement at a time, distinguishing “works” from “works well.”

Why learn:

Isolated changes are easy to test and revert.

Key concepts:

Layers; increment; measure before and after each change.

What it is:

The recommended sequence of improvements: handle errors, then logic, then output quality, then performance.

Why learn:

Solving what matters most first keeps you from optimizing what still breaks.

Key concepts:

Robustness before polish; performance last.

What it is:

Confidence marker + code node + IF + a "let's research this and get back to you" draft when there's no answer in the knowledge base.

Why learn:

Ensures a decent response even when the agent doesn't know.

Key concepts:

Confidence score; IF branch; fallback draft.

What it is:

Process only emails newer than X minutes, using the "newer than" syntax in the trigger.

Why learn:

Avoid reprocessing old history on every run.

Key concepts:

Time window; trigger filter; efficiency.

What it is:

Detect and ignore no-reply messages, out-of-office replies, and newsletters.

Why learn:

Don’t waste processing (and tokens) on messages that don’t need a response.

Key concepts:

Sender patterns; watch out for uppercase and lowercase letters (case sensitivity).

What it is:

Update the agent’s system prompt and fallback draft so they sound like the brand.

Why learn:

Consistency of voice conveys professionalism.

Key concepts:

Tone set in the prompt; aligned fallback; example review.

What it is:

Extract the name from the email signature; use "Hello" as a fallback when there's no name.

Why learn:

Personalization improves the perceived quality of the response.

Key concepts:

Name extraction; graceful fallback; dynamic greeting.

What it is:

A high/medium/low badge derived from the vector store score, for internal review.

Why learn:

Indicates which drafts need human review before sending.

Key concepts:

Score → range; confidence badge; triage for review.
